# 交易状态与异常恢复

在第一次创建订单或进入支付前阅读本文件；发生超时、断线、接管、中断或恢复运行时再次按对应情况检查。这里是执行规则，没有后台控制器；必须用可用工具和官方页面落实。

## 最小记录

为本次操作维护一份最小状态记录。能安全写入本地时，在交易动作前保存到仓库外的私有临时目录；禁止保存到 Git 工作树或自动同步目录。不具备持久化能力时在当前会话中记录，并在任何新会话或中断恢复后先查官方订单，不能假定上次失败。

记录字段：

| 字段 | 用途 |
| --- | --- |
| `run_id`、`updated_at` | 本次操作标识和含时区的更新时间 |
| `authorization` | 用户允许的范围、总价上限、期限、最大成功订单数 |
| `event`、`performance` | 页面显示的准确演出、场次及可见标识 |
| `quantity`、`ticket_summary` | 票数、票档或座位，不含入场码 |
| `attendee_refs` | 脱敏的观演人映射；不含证件号码 |
| `currency`、`total_fen` | 币种及整数分总价；未知为 `null` |
| `state`、`order_reference` | 已核实的状态及订单号；未知为 `null` |
| `platform_deadline` | 官方页面显示的截止时间，不能自行猜测 |
| `last_action`、`next_action` | 上次已尝试的动作和下一步核对事项 |

记录只是恢复线索，不能代替官方交易状态或实现跨机器互斥。无法确定是否有另一个流程正在购票时，暂停新的交易动作并核对。完成后按用户的留存要求处理临时记录；不复制浏览器凭据或敏感截图。

## 状态与可执行动作

| 状态 | 需要的依据 | 下一步 |
| --- | --- | --- |
| `PREPARED` | 条件明确，尚未提交 | 核对授权和现有订单后可选票 |
| `SELECTED` | 当前页已选中票 | 检查结算详情；不能声称已锁票 |
| `SUBMISSION_PENDING` | 即将提交，或提交后尚未得到结果 | 记录动作；已点击则等待或核对，禁止再次点击 |
| `SUBMISSION_UNKNOWN` | 提交超时、断线、崩溃等 | 查询官方订单，暂停新订单 |
| `UNPAID` | 官方订单号与待付款状态 | 核对有效期、金额与授权后进入该订单支付 |
| `PAYMENT_PENDING` | 该订单正在支付或等待用户认证 | 保留同一次支付，等待或核对 |
| `PAYMENT_UNKNOWN` | 支付后结果缺失或互相矛盾 | 核对同一支付和官方订单，禁止重新付款 |
| `PAID` | 官方订单确认已付款 | 检查出票/配票，不重复买票 |
| `ISSUED` | 官方票夹或订单确认出票 | 汇报完成及入场方式 |
| `FAILED_OR_CANCELED` | 官方明确失败/取消，且无未决付款 | 授权仍有效时才考虑重新购买 |

`PAID` 与 `ISSUED` 分开保存。平台状态暂不可读取时保持未知，不把本地等待结束映射为失败。字段名是内部记录约定，不能假定为大麦 API 返回字段。

## 结果不明时

1. 暂停所有新的提交和付款动作，记录最后一次已尝试动作。
2. 在同一账号的官方订单记录中查找与本次演出、场次、数量、金额和时间相符的订单。只凭演出名相同不能认定是同一订单；多个候选无法区分时需要用户核对。
3. 找到订单后打开详情，核实订单号、当前状态、金额和页面显示的期限；继续处理已有订单。
4. 未立即找到订单并不证明提交失败。允许有界的只读状态检查，遵守平台限流与本次截止时间。明确失败或取消且没有未决付款，才可根据仍有效的授权考虑另一次购买。
5. 若付款服务与大麦状态冲突、网络持续不可用或期限已到仍无法确认，报告“结果未确认”，提供官方订单入口和待核对事项。必要时建议用户联系官方客服；不要自动重付、取消或创建替代订单。

## 需要用户接管时

- 验证码、短信验证、身份核验及支付认证：让用户在当前官方页面完成。不要在聊天中收集或代填挑战答案。
- 用户接管期间也可能已经下单或付款。接管后先查页面和订单，不能直接重复之前的动作。
- 会话失效：重新登录后核对账号，再检查已有交易。不能从“登录成功”直接跳回提交。
- 价格、座位、观演人或场次变化：重新执行全量约束检查。超出授权时展示变化；覆盖原授权时无需重复询问。
- 用户要求停止：停止新交易动作，简短说明是否已有待付款订单、未决支付或已付款订单。用户没有授权取消时，不代为取消。

## 结束条件

成功出票、用户要求停止、超过用户截止时间、平台拒绝当前操作方式，或无法解决的交易不确定性，均停止进一步购买。仍有待付款或未决支付时，把准确状态和可执行的下一步交付给用户；不得为了给出“成功/失败”二选一而猜测。
